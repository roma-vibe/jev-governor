# jev-governor: интерфейс настроек

Локальная страница для настройки мода: пороги Jev, модели, агенты-специалисты и навыки,
сжатие контекста, статистика и журнал решений. Сервер слушает только `127.0.0.1`.

## Установка и сборка

Из корня проекта (нужен Node 23.6 или новее: сервер и `hooks/lib` написаны на TypeScript, Node запускает их напрямую):

```sh
npm run ui:install   # зависимости интерфейса (Vue, Vite, Tailwind)
npm run ui:build     # проверка типов (vue-tsc) и сборка в ui/dist
```

## Запуск

```sh
npm run ui                                   # http://127.0.0.1:4777
node ui/server.ts --port 4777 --data <dir>   # свой порт и папка данных
node ui/server.ts --detach                   # в фоне; повторный вызов только печатает адрес
```

- Папка данных: `--data`, иначе `$JEV_GOVERNOR_HOME`, иначе `~/.claude/jev-governor`
  (формат файлов: `docs/DATA.md`).
- Язык интерфейса: `ui.language` в `config.json` (`en` по умолчанию, `ru`), меняется в «Settings → Interface».
- Порт: `--port`, иначе `ui.port` из `config.json`, иначе 4777.
- В режиме `--detach` процесс пишет pid в `<data>/ui.pid`; остановить: `kill $(cat <data>/ui.pid)`.
- Пока `ui/dist` не собран, сервер показывает подсказку `npm run ui:build`, а API уже работает.

В Claude Code команда **`/jevg ui`** запускает сервер в фоне (`--detach`) и печатает адрес:
`jev-governor UI: http://127.0.0.1:4777`.

## Разработка

```sh
npm run ui                 # сервер API на :4777 (в одном терминале)
npm run ui:dev             # Vite на :5173 с прокси /api на :4777
JEV_UI_PORT=4791 npm run ui:dev   # если API на другом порту
```

## Безопасность

- Только `127.0.0.1`; заголовок `Host` должен быть локальным.
- Любой запрос, кроме GET, требует заголовок `X-Jev-Governor: 1`, а `Origin` (если есть) должен
  совпадать с адресом сервера.
- Ключ OpenRouter никогда не отдаётся в API: интерфейс видит только «найден / не найден» и источник
  (переменная `OPENROUTER_API_KEY`, файл `jev.keyFile` или `.openrouter_key` в корне проекта).
  Новый ключ сохраняется в `jev.keyFile` с правами 0600.
- Вкладка «Проекты» только читает папки проектов: список папок и небольшие файлы (до 256 КБ), ссылки на файлы вне
  проекта не разворачиваются, сканирование неглубокое (корень и подпапки первого уровня, без `node_modules`, `.git`,
  `target`, `dist`, `build`, `.venv`, `vendor`). Внутрь проекта сервер ничего не пишет и сборку там не запускает; из
  внешних программ вызываются только `git` (чтение, 3 с), `open` и `osascript`.
- «▶ В терминале» запускает только команду, сохранённую в записи проекта (по её id), а не текст из запроса: через
  `osascript` в Terminal.app, одной строкой `cd '<папка>' && <команда>`. Команды с переводом строки или похожие на
  секрет (токен, пароль, ключ) не сохраняются и не запускаются.
- Имена агентов и навыков проверяются по `NAME_RE` до любых операций с файлами; запись атомарная
  (временный файл и rename); тело запроса не больше 256 КБ.

## Вкладки

- **Обзор**: статистика за 1/7/30 дней, карточка «Экономия» и последние решения (обновляется каждые 10 секунд).
- **Экономия**: сколько мод сэкономил за 1/7/30 дней в долларах API по прайс-листу Anthropic (`hooks/lib/savings.ts`):
  «точно» (выбор модели, обрезка выводов, сжатие контекста: по журналу), «по оценке» (меньший уровень усилия, сжатия вместо
  пересказа Claude Code), расходы на Jev, чистая выгода, фактический расход и «без мода было бы»; разбивка по источникам,
  по дням и по проектам, журнал событий. Параметры расчёта — раздел «Расчёт экономии» в настройках. API:
  `GET /api/savings?days=N[&project=<id проекта>]`; краткие итоги (`savings`) есть и в `GET /api/stats`; они же на
  карточке «Экономия» вкладки «Обзор» и в полосе на странице проекта.
- **Проекты**: проекты из истории сессий Claude Code (`~/.claude/projects`). На странице проекта: ветка git и
  последний коммит, статистика из журнала за 30 дней, команды по группам (запуск, сборка, тесты, проверки, база данных,
  деплой, прочее). Команды находятся в `package.json`, `Makefile`, `Cargo.toml`, `justfile`, `pyproject.toml`,
  docker compose, `.claude/launch.json` и в README / AGENTS / CLAUDE / CONTRIBUTING, плюс команды, которые Claude успешно
  запускал в проекте (`ledger`, `kind: command`), и добавленные вручную. Записи лежат в `<data>/projects/<id>.json`;
  описания команд пишет открытая сессия Claude Code с модом через `<data>/describe/<id>-<ts>.json` (пока её нет,
  показываются черновики из файлов проекта).
- **Настройки**: все поля `GovernorConfig` с пояснениями; ключ и проверка Jev.
- **Агенты**: список, редактор, генерация по описанию (черновик создаёт открытая сессия Claude Code с модом).
- **Навыки**: общие куски знаний для агентов.
- **Журнал**: записи `ledger/` с фильтрами и просмотром сырого JSON.
